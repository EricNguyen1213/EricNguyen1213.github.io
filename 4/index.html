Recover Homographies


To warp the images to be able align, I needed to be able to approximate the transformation between the points in the image. That is doable via calculating the homography matrix. The homography matrix has 8 unknowns, but this is solvable using at least 4 points of correspondences. For stability, it is better to use more than 4 points for overdetermination. The approximation could be done with Least Squares.

Warp the Images


To successfully conduct a warp on an image to align with another, here is what I did. First, I computed corresponding H matrix. Using that matrix, I transformed the 4 corners of the image and recorded the min and max of both the X and Y dimensions in order to determine the bound box. I also used them to create a translation matrix to ensure that when I conduct the transformation, the points would be transformed to valid nonnegtive points on the output bound box. I inverted the transformation such that I could go from the output box to the input box such that I could ensure every pixel in the output box is accounted for. Using this inverse transformation, I applied two different method of sampling. One was Nearest Neighbor where the transformed result is rounded to the nearest input pixel, and I would just sample the values from there. The other was Bilinear Interpolation where I would use the transformed result to calculated a weighted combination of the values from all adjacent pixels: top-left, top-right, bottom-left, and bottom-right.

Comparison

In terms of quality, in high resolutions, the results of either methods of samplings are just about the same in view with barely noticeable differences if at all. In lower resolutions, bilinear interpolation is better, resulting in quality with pixels that is weighted on its surrounding instead of solidly choosing one pixel value like with nearest neighbor. The tradeoff is that bilinear interpolation is twice as expensive as nearest neighbor in time. In the tests run above, the run time for bilinear interpolation has always resulted in run time is very near to twice that of nearest neighbor.

Blend the Images into a Mosaic

Procedure

Due to the sheer size of my inputs and the number of them, I have to unroll each image into a cylindrical projection to prevent the bound boxes from blowing up towards the end. With that, I also converted the cartesian correspondences into their cylindrical version to be compatible for this implementation. Next, I computed all the H Matrices for a set of images. Choosing 1 middle image to be the anchor, I proceeded calculate the H matrices spanning outward from the anchor, which means it is the images to the left and the images to the right of the anchor that have to project towards the anchor. As I calculate the H matrices for images that were farther away, I matrix-multiplied previous H matrices onto those current ones to account for the image transforming towards images were also transforming. It was like a chain. After getting all the H matrices, I proceeded to transform the four corners of every image in the set with their corresponding H matrix to obtain the definitive minimum and maximum of the X and Y dimensions to create the final bound box every transformed image is going to be pasted on as well as to gather metadata such that I can properly translate the warped images to the right spot on the final bound box. I then proceeded to generate the warped image using the Part 3's function but with the corresponding H matrix I created by cascading H matrices. I used the local minimum and maximum dimensions of their bound boxes in conjuction with the definitive minimum and maximum to find the right x and y translation for the warped images onto the final bound box. Before combining the warped images all together, I calculated a weighting system per layer which involves reducing the weights of pixels as they near the edge of the warped image. This is because the overlap will happen around the edges. This is all normalized in the end to keep values balanced and valid. After combining all layers, a panaoramic view would be returned.
