My implementation includes zero padding of a few modes: same & full. Same pads the input image just enough to leaves the output image the same dimensions as the original input image. It is still zero padding, so the there exist thin dark borders around the image due to contribution of 0 weights. Full pads the image to make the output image bigger after convolution to reveal the effects of every kernel filter interaction with the image. This along with zero padding made the dark boundaries thicker.



My 4 for loop implementation iterated through every pixel of the output image. For each output pixel, it calculated its value by iterating through the filter operation pixel by pixel. Runtime for it was long, reaching nearly 2 minutes for applying the box filter. My 2 for loop implementation unrolled the pixel by pixel filter operation, doing the calculations for many output pixels at once instead of one at a time. The only iterating it needed to do was for the size of the kernel itself. Runtime for it was quick, making the box filter application around 1 second. In comparison to Scipy's convolution function, my 4 for loop implementation is miles behind in runtime but my 2 for loop implementation is very close, nearing the same runtime, and a few times has a smaller runtime like with the application of the Dy finite difference filter.

My choice of threshold 0.2828 was motivated by my desire to balance noise and edges I thought were valuable. The biggest source of noise in the edge image originated in the grass, leaving lots of noise scattered along the bottom of the image. I slowly incremented up the threshold to gauge the reduction of noise. Past this threshold, the details of the man and the camera's edges were getting reduced. While some noise is present, I believe its amount is low enough that it did not justify further reducing the details of the man and camera.

When an image is blurred via a Gaussian filter, the image is going through a filter such that only low frequencies are permitted while high frequencies are attentuated. An unsharp mask filter takes advantage of this. Since images after a blur filter are of low frequencies, taking the difference of it from the original would leave the high frequencies. These high freqeuncies are then added back to the original, sometimes scaled up, further amplifying the high frequencies in the original, making it "sharper". Sharpening is not always good, as doing it in an extreme degree could sharpen noise.

When resharpening an image that went through a blur filter, it creates an image that closely resembles the original.

When attempting to create hybrid images, it is best that the images are aligned for a better viewing experience. To do so, I chose specific points from each image that I wanted to be 1 to 1 with each other and shifted, rotated, and resized the images to make that happen. In my case, I chose to align the eyes.

Using Gaussian Filters, I can create a low pass filter that blurs an image, leaving low frequencies, and a high pass filter that retains the higher frequencies only. Each filter has there own cut-off frequencies. The higher the cut-off frequencies, the more gets filtered out from either. The lower the cut-off frequencies, the more the finer details get retained. For all these examples, the cut-off frequencies were decided via trial and error to find the right balance of the insensity of each image. I wanted to ensure that neither images overpowered each other, making it difficult to gauge what could be seen.
